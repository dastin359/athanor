CCARC3 solver trace audit

Per-run audit from saved claude -p streams · baseline-free arm

Every game the harness runs is a claude -p session recorded with --output-format stream-json --verbose. That NDJSON is the only place the parent/child structure exists, so the spans behind these figures are reconstructed from it rather than from any telemetry exporter — nothing was re-run to produce this page.

The spans themselves are not embedded here. They live in evidence/ccarc3/trace_audit/spans.json.gz — __NSPANS__ spans across __NGAMES__ runs, at full fidelity. They used to ship inside this page to drive an interactive tree, which cost 13.8 MB and forced 4,143 tool payloads to be truncated to 1,000 characters to fit the artifact ceiling. The published page was therefore the lossy copy of its own evidence, which is the wrong way round. Every figure below is still derived from the full store at build time.

Where the wall clock actually goes

__LLM_PCT__% of a solver's wall clock is spent waiting on the model, not running its own code. The agent writes a great deal of Python — __BASH_CALLS__ Bash calls across __NGAMES__ games — but at a __BASH_MEDIAN__ s median, most of which is interpreter start-up and import numpy on 64×64 grids. So concurrency is limited by model latency and quota rather than by local compute.

These four figures are computed from the span data on this page at build time, not written by hand. An earlier version of this paragraph read 82% … 949 Bash calls across ten games … 1.36 s median and stayed on the page after it grew to 25 games, so it was describing a build that no longer existed. Anything quoted here that can be derived is now derived.
