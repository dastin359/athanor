CCARC3 solver trace audit

Span trees rebuilt from saved claude -p streams · baseline-free arm

Every game the harness runs is a claude -p session recorded with --output-format stream-json --verbose. That NDJSON is the only place the parent/child structure exists, so these span trees are reconstructed from it rather than from any telemetry exporter — nothing was re-run to produce this page. A span's parent is the tool named by its parent_tool_use_id, or the session root when it has none.

Where the wall clock actually goes

__LLM_PCT__% of a solver's wall clock is spent waiting on the model, not running its own code. The agent writes a great deal of Python — __BASH_CALLS__ Bash calls across __NGAMES__ games — but at a __BASH_MEDIAN__ s median, most of which is interpreter start-up and import numpy on 64×64 grids. So concurrency is limited by model latency and quota rather than by local compute.

These four figures are computed from the span data on this page at build time, not written by hand. An earlier version of this paragraph read 82% … 949 Bash calls across ten games … 1.36 s median and stayed on the page after it grew to 25 games, so it was describing a build that no longer existed. Anything quoted here that can be derived is now derived.

What the traces show

Scope note. The findings below were computed on the ten-game build of 2026-08-05 and their counts — 949 Bash calls, 17,889 stream lines, 883 thinking blocks, 972 turns, 11,250 spans — describe that set, not the __NGAMES__ games now on this page. They are left as written because each is a claim about the runs it analysed and re-deriving them is a separate piece of work; they are marked rather than quietly restated so no number here is mistaken for a current one.
